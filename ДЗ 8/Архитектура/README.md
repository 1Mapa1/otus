# Архитектура (ДЗ 8)

Здесь собран ответ на **п. 0** домашнего задания: какой паттерн распределённой транзакции использован, как устроен процесс, где компенсации и как заказ доходит до финального статуса. Материалы разбиты на три файла, чтобы сначала было видно **поле вариантов**, затем **логику выбора**, затем **контракты и диаграммы** выбранного решения.

## Рекомендуемый порядок чтения

1. **[Виды реализации распределенной транзакции.md](./Виды%20реализации%20распределенной%20транзакции.md)** — обзор подходов (2PC, saga в HTTP, saga через worker + HTTP, saga + Kafka commands, choreography), плюсы/минусы и сводная таблица. Удобно как «карта решений» перед чтением остального.
2. **[Аргументация выбора Saga Orchestration через background worker и HTTP-команды.md](./Аргументация%20выбора%20Saga%20Orchestration%20через%20background%20worker%20и%20HTTP-команды.md)** — постановка задания, почему saga и orchestration, почему HTTP для шагов и Kafka только для итоговых событий, почему worker вместо полного сценария в `POST`, и краткое сравнение с отвергнутыми альтернативами.
3. **[Saga Orchestration через background worker и HTTP-команды.md](./Saga%20Orchestration%20через%20background%20worker%20и%20HTTP-команды.md)** — детальное описание реализации: участники, внешний и внутренний API, mermaid sequence-диаграммы, IDL по эндпоинтам, таблицы компенсаций и обработки ошибок.

В начале документов **«Аргументация…»** и **«Saga Orchestration…»** есть блок **«См. также»**. В **«Видах реализации…»** навигация в начале и ссылки на следующие материалы в конце (раздел «Итог»).
